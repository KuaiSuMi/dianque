# 点雀 · 日麻点棒显示

三台或四台手机各作为一个数显终端。用于线下日麻没有实体点棒时的点数交付、立直、本场与对战记录。

## 启动

需要 Node.js 22.13 或更新版本。首次运行：

```powershell
npm install
npm run build
npm start
```

电脑打开 `http://localhost:3000`。四台手机连接同一 Wi-Fi，打开启动终端输出的局域网地址，例如 `http://192.168.1.10:3000`。电脑需保持运行，Windows 防火墙需允许该私有网络上的 Node.js 入站连接；不要关闭防火墙。路由器的访客隔离、校园网客户端隔离可能阻止手机访问。

默认房主起庄，其余玩家按座位顺序加入。满员后，房主可在房间大厅点击“随机选座”，重新分配座位，东家起庄；也可按当前座位直接开局。房主身份不随座位改变。二维码和房间码都可邀请，房间码为四位大写英文字母，输入小写会自动转换为大写。

开发时运行 `npm run dev`，先构建页面再启动 Wrangler。后端改动自动重新加载；前端改动后停止开发服务，再运行 `npm run dev` 并刷新页面。修改端口用 `npm start -- --port 3001`。本地数据位于 `.wrangler/state`，与线上隔离。

## 使用

- **界面与动效**：跟随系统深浅色，提供玻璃悬浮工具栏、可拖动分段选择器、弹性弹层、页面与表单过渡、点数更新反馈。系统开启减少动态效果、减少透明度或增强对比度时自动调整。
- **房间规则**：创建时或房间大厅的“房间设置”中，由房主选择三人/四人、东风场/南风场及起始点数（1,000～1,000,000 的整百数）。已有四人入座时不能改为三人。三人模式使用东、南、西三个座位，每场三局；自摸损，两家按原档支付，不补北家份额。
- **场况调整**：对局中，房主可在“牌桌设置 → 修改当前场况”设置场风、局数、本场、供托及所有玩家点数。修改同步全桌、记入流水并支持撤销/重做；改变局数会清除立直标记。存在待确认支付或流局投票时不可修改，过期表单需重新打开。
- **对局锁定**：对局及对战结算中隐藏离开入口；打开首页或其他房间链接会恢复当前牌桌。创建、入座及切换房间按服务端账号检查；房主确认结算后解除。同一账号在其他设备登录会恢复原座位，不能重复占座。
- **退出房间**：在房间大厅点击退出会立即释放座位，房主退出时自动转交给剩余座位中最靠前的玩家。同账号其他页面同步退出；重新加入按新玩家入座，历史战绩保留。断网或锁屏不视为主动退出。
- **显示**：本人为大号七段数显，三家按上家、对家、下家排列；显示当前风位、局数、本场、供托与在线状态。各家点数右下方显示我与该家的点差，正数为领先，负数为落后。起庄标记固定在起庄者，当前庄家用暖色风位标记。
- **荣和**：放铳者点击收款人头像，选择常规点数或自定义金额并确认。收款方二次确认后扣款、收款、处理供托并自动换局。
- **双响 / 三响**：在荣和表单勾选多位和牌者，分别选择或填写金额，整批发起；所有和牌者确认后只结算一次。
- **自摸**：赢家点击“自摸”，或付款方点击赢家头像后选择“对方自摸”。快捷选择一次填好各家金额，也可自定义逐家输入；每家分别确认付款，再由赢家确认收款。四人模式三家支付，三人模式两家支付，全部同时入账，只换一次局。
- **金额**：常规点数按庄家/子家提供快捷档位，荣和自动加每本场 300 点，自摸每个付款方各加每本场 100 点。双响/三响的本场只加给放铳者下家方向最近的和牌者。自定义输入为已含本场的最终金额，须为 100 的正整数倍，系统不再追加本场。两种方式均不含供托；系统不判断番符或牌型。切换输入方式会清空金额，避免重复加算。
- **立直**：确认后扣 1000 点进入供托；本局不得重复立直，持有点数不足 1000 时不可立直。
- **番符提示**：选择常规点数后，在该和牌者的金额按钮下方显示对应番符；同一点数的不同组合一起列出，多家荣和分别显示在各自区域。自摸提示位于自摸档位下方。增减和牌者、切换荣和/自摸和常规/自定义时，内容平滑展开收起；减少动态效果时取消高度动画。提示按不含本场的所选档位计算，支持庄闲、荣和、自摸和满贯以上档位；三麻仍按原档说明。低于满贯的点数对应关系参考 [Riichi Book I 第 6 章](https://mahjong.dk/hubfs/Mahjong%20documents/Riichi/RiichiBook1.pdf#page=208)，沿用现有不切上满贯的档位。
- **流局**：全员分别点击流局并选择听牌/未听，无需同一秒操作。确认后弹窗保留并显示进度，最后一人确认后结算听牌罚符（四人共 3,000 点，三人共 2,000 点），换局并自动关闭弹窗。完成前可撤回自己的确认；有立直记录的玩家只能报听牌。
- **撤销 / 重做**：作用于全桌最近一笔已落账操作，同时恢复点数、局数、本场、供托和立直。待确认交易或流局投票须先取消。撤销后发生新操作会清空重做分支。
- **结束与续局**：房主点击牌桌顶部的“结束对战”，全员进入结算页。剩余供托归第一名，同分按座次顺序决定；结算页显示已含供托的最终分数。房主可修改分配供托前的分数，保存后全员同步，供托归属随排名更新。房主点击“确认结算并返回大厅”后，供托一次性入账并清零，全员回到原房间大厅，保留房间码和身份。房主可点击“开始对局”或先“随机选座”；下一场重置点数、局数、本场、供托和立直。房主标识不随换座改变。确认结算后禁止撤销或重做，已保存的成绩不再变动；确认前房主仍可撤销结算中的操作。待确认支付或流局投票期间不可结束；结算中的刷新、重连和服务重启都会恢复结算页。
- **待确认支付**：出现新支付时，全员的确认弹窗自动打开；可以手动关闭后从牌桌提示条再次打开。同一笔支付的确认进度更新不会重复弹出，支付完成或取消后自动关闭。
- **记录**：首页可回到尚未退出的房间；房间大厅和牌桌中均可查看记录，按场次切换排名、每笔流水、已撤销记录，并导出选中场次的 JSON。历史保存当场的玩家座位和点数，不受下一场换座影响。

## 规则边界

庄家和牌或流局听牌连庄；连庄、流局增加本场；子家和牌后本场清零。流局不清空供托。多家荣和时供托归放铳者下家方向最近的和牌者。即便分数为负也可记录实际支付。

东风场 / 南风场是对战约定，不自动执行终场、南入/西入、飞人、止庄与马点精算，由房主明确结束。特殊中途流局、流局满贯、罚款不在本版规则内，不能用普通和牌交付代替这些操作。

## 安装到手机

完整 PWA 安装和常亮屏幕需浏览器支持，且使用 **HTTPS（或本机 localhost）**。

- Android：HTTPS 页面中选择浏览器的“安装应用”或“添加到主屏幕”。
- iPhone：在 Safari 中“分享 → 添加到主屏幕”。
- 局域网 HTTP 可以直接四人记分；不保证浏览器提供安装或常亮功能。

## 账号与战绩

注册只需昵称和密码。昵称唯一，忽略字母大小写与全半角差异；昵称 1～12 个字，密码 8～128 位。当前不提供密码找回，请保存密码。

首页点击昵称旁的“我的对局”，查看三人、四人各自的完成场数、平均顺位及最近 20 场顺位折线图（从左到右由早到晚，第一位在上方）。记录每页 20 场，点击可看最终点数和流水。只统计房主已确认结束的对局，同分按当场座位顺序决定顺位；不计算马点。确认后的成绩保留，退出房间不影响个人战绩。

同一账号可跨设备登录、回到原座位。测试多个玩家请使用不同账号和浏览器配置文件；同一配置文件下的多个标签或无痕窗口可能共享登录 Cookie。

## Cloudflare 发布

Workers 静态资源托管页面，SQLite Durable Object 保存账号、房间和对局，原生 WebSocket 休眠接口同步状态。无需 Node 服务器、D1 或 KV。旧匿名数据库已按要求删除，不导入新账号。

### 从 GitHub 自动部署

在 Cloudflare 控制台进入 **Workers & Pages → 创建应用 → 连接 GitHub 仓库**，选择 `KuaiSuMi/dianque`，填写：

| 配置 | 值 |
| --- | --- |
| Worker 名称 | `dianque`，与 `wrangler.jsonc` 一致 |
| 生产分支 | `main` |
| 根目录 | 仓库根目录 `/` |
| 构建命令 | `npm run build && npm test` |
| 部署命令 | `npx wrangler deploy` |

Cloudflare 自动安装依赖，`.node-version` 指定 Node.js 22；构建和测试通过后才发布。首次连接时完成 GitHub 仓库授权，部署凭证使用 Cloudflare 自动生成的 API token。发布时按仓库配置创建 Durable Object 绑定；后续推送到 `main` 自动部署。使用 Workers Free 套餐。

配置入口和构建行为见 [Workers Builds 文档](https://developers.cloudflare.com/workers/ci-cd/builds/configuration/)；Node.js 版本文件见 [构建环境文档](https://developers.cloudflare.com/workers/ci-cd/builds/build-image/)。

### 本机命令行部署

```powershell
npm ci
npm run build
npm test
npx wrangler login --scopes account:read user:read workers_scripts:write
npm run deploy
```

首次发布时选择自己的 Cloudflare 账号；如尚未设置 `workers.dev` 子域名，在控制台完成设置。手机使用输出的 HTTPS 地址访问，无需同一 Wi-Fi，也不需要电脑保持运行。已有其他同名 Worker 时，先修改 `wrangler.jsonc` 中的 `name`，避免覆盖无关项目。

`new_sqlite_classes` 是首次创建 Durable Object 所需的注册配置。后续发布保留该配置与绑定名称，勿删除线上命名空间。Wrangler 登录凭证由 CLI 保存，不写入仓库。

[免费额度](https://developers.cloudflare.com/durable-objects/platform/pricing/)：Durable Objects 每日 100,000 请求、13,000 GB-s，SQLite 每日 500 万行读、10 万行写、账号总存储 5 GB。免费额度用尽后会拒绝请求，日额度次日恢复；不要启用 Workers Paid。静态页面、API 请求和数据库写入计量不同，不能将 100,000 请求理解为支持 100,000 场。

当前使用一个 Durable Object 统一处理应用，以 SQLite 同步事务保证房间锁定、分数和个人战绩同时落账，适合小规模牌友使用；所有房间共享这一实例的吞吐量。WebSocket 使用休眠和自动心跳响应，空闲连接不保持实例活跃。

## 数据与运行

- 密码使用随机盐与 PBKDF2-SHA256（600,000 次）；不保存明文。登录失败和注册均有限流。
- Cookie 为 HttpOnly、SameSite=Lax，线上启用 Secure，30 天过期；退出立即撤销该会话并断开其同步连接。
- API 与 WebSocket 同源校验。服务端验证成员、房主权限、金额、版本和幂等编号。历史明细只允许当场参赛账号读取。
- 操作通过 HTTP 提交，持久化后再广播。断网时暂停操作，不做离线合并；重连获取最新状态。
- 房间码用于邀请，不是登录凭证；未坐满的房间可由知道房间码的已登录玩家加入。
- 线上数据保存在 Cloudflare；本地 `.wrangler/state` 仅用于开发。删除本地目录不会清空线上记录。可从对战记录导出单场 JSON。
